# AI 接手入口 / 文档路由入口怎么建

这份说明是 base 的通用规则。

可直接迁移到新项目的 AI 接手入口模板见：

- `skills/cool-project-stack/templates/ai-entry-template.md`

新项目正式文件建议命名为：

- `docs/00-system/AI接手入口.md`

目标不是多写一份大文档，而是给项目补一个统一入口，让任何 AI 接手时，先知道：**这次应该先看哪份正式文档，再回答，再决定要不要进入完整流程。**

## 1. 什么是“AI 接手入口 / 文档路由入口”

它是一份项目级入口文档，通常放在：

- `docs/00-system/AI接手入口.md`

它要解决的问题是：

- 新接手的 AI 不知道先看哪里
- 用户问的是功能、进度、代码落点、设计原因还是项目坑位，经常混在一起
- 项目文档多了以后，只看 `docs/README.md` 还不够快
- 后续 AI 容易直接扫代码或直接套流程，没先找对文档

这份文档本质上是**接手时的文档路由器**。

## 2. 它和其他文档的关系

### 和 `docs/README.md` 的关系

- `docs/README.md` 是项目文档总入口
- 它负责全局导航：文档结构、常见场景、模块目录、维护入口
- `AI接手入口.md` 是更靠前的一层“接手路由”
- 它负责先判断：用户这次在问什么，然后把 AI 导向对应正式文档

简单理解：

- `docs/README.md` 管全局目录
- `AI接手入口.md` 管接手时先跳哪份文档

### 和模块 README 的关系

- 模块 `README.md` 是模块正式入口
- 它负责模块背景、版本规划、阅读顺序、当前版本入口、长期约束入口、代码落点
- `AI接手入口.md` 不替模块 README 写细节，只负责把 AI 导过去

### 和项目开发维护索引的关系

- `项目开发维护索引.md` 负责长期维护视角
- 它回答：正式文档入口有哪些、常见开发动作先看哪里、哪些经验回灌 base、哪些只留项目内
- `AI接手入口.md` 负责问题路由视角
- 它回答：用户这次问的到底是哪类问题，先跳哪份文档

可以同时存在，不冲突：

- `AI接手入口.md` 更像“先分流”
- `项目开发维护索引.md` 更像“长期维护导航”

### 和项目专属坑位文档的关系

- 项目专属坑位文档记录项目私有坑、兼容点、历史偏差
- `AI接手入口.md` 只需要说明：当用户问“有没有项目特有坑 / 为什么和 base 不一样”时，先去看坑位文档
- 不要把坑位全文复制到入口文档里

### 和任务执行卡的关系

- 任务执行卡负责记录当前任务 / 当前版本推进状态
- 用户问“做到哪了 / 当前开发到哪里了”时，应由 `AI接手入口.md` 把 AI 导向任务执行卡
- 入口文档本身不维护任务进度

## 3. 这份入口文档至少要回答什么

一份合格的 `docs/00-system/AI接手入口.md`，至少要明确：

1. AI 接手时默认先看什么
2. 用户问“某个功能是什么”时先看哪里
3. 用户问“做到哪了 / 当前开发到哪里了”时先看哪里
4. 用户问“要改哪里”时先看哪里
5. 用户问“为什么项目这么写”时先看哪里
6. 用户问“有没有项目特有坑 / 为什么和 base 不一样”时先看哪里
7. `docs/README.md`、模块 README、项目开发维护索引、项目专属坑位文档、任务执行卡分别负责什么
8. AI 回答时必须先定位文档，再给结论

## 4. 它不是做什么的

### 不是默认每次都触发 superpowers

- 用户只问一个小功能、一个字段、一个页面，不代表必须升级流程
- 是否调用更强 skill 或更重流程，仍按任务复杂度和项目规则判断
- 入口文档只负责先找对文档，不负责强行升级任务

### 不是默认每次都完整走 docs-first / project-stack

- 小修复、小排查、小范围说明，可能只需要定位到模块 README 或相关文档后直接回答 / 直接改
- 只有当任务本身达到需要阶段化文档流的级别时，才进入 docs → review → dev
- 是否进入完整流程，仍由任务分级、影响范围、既有规则决定

## 5. AI 默认执行规则

如果你是 AI，在项目里接手任务时：

1. 先看 `docs/README.md`
2. 如果项目已建立 `docs/00-system/AI接手入口.md`，再看它
3. 先判断用户问题类型，再跳到对应正式文档
4. 确认依据后，再回答用户或开始改代码
5. 不要跳过文档定位直接靠扫代码猜业务
6. 不要把入口文档误用成知识库

## 6. 什么时候建议项目补这份文档

满足下面任一条，就建议建立：

1. 项目已经进入长期维护阶段
2. 正式文档已经不止一层，新 AI 不容易快速找入口
3. 项目已经同时存在 `docs/README.md`、模块 README、维护索引、坑位文档、任务执行卡
4. 团队明确希望“AI 接手时先找对文档再回答”
5. 项目里已经出现“别人问一句，AI 就直接扫代码或直接套流程”的问题

## 7. 最小落地动作

如果要在具体项目中落地，最少做这几步：

1. 新增 `docs/00-system/AI接手入口.md`
2. 更新 `docs/README.md`，给它正式入口
3. 如有新人入口文档，再补一句“不知道从哪里接手，先看 AI 接手入口”
4. 检查模块 README、维护索引、坑位文档、任务执行卡是否已有稳定落点
5. 确保 AI 能走通这条链路：
   - `docs/README.md`
   - `docs/00-system/AI接手入口.md`
   - 模块 README / 维护索引 / 坑位文档 / 任务执行卡

## 8. 一句话记住

AI 接手入口 / 文档路由入口的目标是：**让任何 AI 先找对文档再回答。**

它不默认升级流程，也不替代任务分级；它只是把“先看哪里”这件事固定下来。

# base 资产边界说明

这份文档说明 base 中哪些内容是通用资产，哪些内容迁移到新项目后必须项目化。

## 通用资产

这些内容可以迁移到新项目：

- `skills/`
- `docs/`
- `README.md` 的结构和入口思路
- `AGENTS.md`
- `project.agent.template.yaml`
- 迁移脚本

迁移后必须根据新项目目录和业务调整变量。

## 不应写死的内容

通用文档中不要写死：

- 本机绝对路径
- 具体项目名
- 新项目真实端目录
- 具体业务模块名
- 某个项目专属状态、字段、权限规则
- 外部 skill 必装假设

这些内容应放到 `project.agent.yaml` 或新项目自己的文档中。

## 可以保留的内容

这些内容可以保留为技术事实：

- `src/modules/base`
- `BaseService`
- cool-admin、Midway、Vue、Uni 等技术栈名称
- 官方文档链接
- 框架规定的目录结构

不要把它们当作迁移变量全局替换。

## 示例管理

示例有教学价值，但必须和规则正文分开。

推荐做法：

- 规则正文写通用原则
- 示例区明确标注“这是示例，不代表项目默认业务”
- 新项目迁移时，用 `EXAMPLE_MODULE` 替换示例模块
- 示例不要混入不可替换的关键流程规则

## README / docs / skills 边界

- `README.md`：项目入口，写给人看。
- `AGENTS.md`：AI 接手入口，写给 agent 看。
- `docs/`：协作文档、流程说明、检查清单、长期维护入口。
- `skills/`：AI 执行规则、读取顺序、任务分级和落地约束。
- `skills/*/templates/`：可复制产物骨架，不写项目事实。

## 迁移原则

一句话：base 提供的是“可实例化资产”，不是“复制后无需调整的成品项目文档”。

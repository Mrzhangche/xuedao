# 一句话启动新项目迁移提示词

这份文档给人复制使用。目标是让 AI 通过一句话完成 base 规范资产迁移。

## 最短提示词

```text
请把 /Users/zhang/Desktop/code/xuedao/base 的 base 规范资产迁移到新项目【项目名】，新项目路径是【新项目绝对路径】，后端目录是【后端目录】，后台目录是【后台目录】，移动端目录是【移动端目录或不启用】，docs 目录是 docs，skills 目录是 skills；请先创建/更新 project.agent.yaml，再 dry-run，确认无高风险冲突后执行 --write，最后检查 migration-report.md、AGENTS.md、README.md、docs/README.md 和迁移后自检清单，修正不适配的新项目路径与入口引用，并汇报改了哪些文件、还有哪些残留需要人工确认。
```

## 填写示例

```text
请把 /Users/zhang/Desktop/code/xuedao/base 的 base 规范资产迁移到新项目 eotoai-care，新项目路径是 /Users/zhang/Desktop/code/eoto-ai/eotoai-care，后端目录是 api，后台目录是 admin，移动端目录是不启用，docs 目录是 docs，skills 目录是 skills；请先创建/更新 project.agent.yaml，再 dry-run，确认无高风险冲突后执行 --write，最后检查 migration-report.md、AGENTS.md、README.md、docs/README.md 和迁移后自检清单，修正不适配的新项目路径与入口引用，并汇报改了哪些文件、还有哪些残留需要人工确认。
```

## 更完整提示词

```text
我要启动一个新项目，请你从 base 完成一次规范资产迁移。

base 路径：/Users/zhang/Desktop/code/xuedao/base
新项目名：【项目名】
新项目 code：【项目 code】
新项目路径：【新项目绝对路径】
项目说明：【一句话说明】
后端目录：【后端目录，未启用就写不启用】
后台目录：【后台目录，未启用就写不启用】
移动端目录：【移动端目录，未启用就写不启用】
文档目录：docs
skills 目录：skills
数据库类型：【postgresql/mysql/其他】
示例模块：【示例模块名】

请按 base 的 MIGRATION.md、AGENTS.md、project.agent.template.yaml 和 skills/cool-project-stack/references/migration.md 执行：
1. 在新项目根目录创建或更新 project.agent.yaml，所有目录映射以它为准。
2. 先运行迁移脚本 dry-run，不要直接覆盖已有文件。
3. 根据 dry-run 结果判断 README、docs、AGENTS、skills 是否有冲突；有冲突先说明处理策略。
4. 无高风险冲突后执行 --write。
5. 生成并检查 migration-report.md。
6. 检查 AGENTS.md、README.md、docs/README.md、docs/00-system/迁移后自检清单.md。
7. 修正明显不适配的新项目路径、入口引用和未启用端说明。
8. 不要全局替换所有 base 字样；不要误改 BaseService、src/modules/base、skill 名称、技术栈名称。
9. 最后用中文汇报：迁移了什么、改了什么、哪些残留需要人工确认、下一步应该做什么。
```

## AI 执行边界

- 可以创建或更新 `project.agent.yaml`。
- 可以运行迁移脚本的 dry-run 和 `--write`。
- 可以修正迁移后的入口文档和明显错误路径。
- 不要删除新项目已有业务文档。
- 不要覆盖新项目已有 README、docs、AGENTS，除非已经先备份或明确合并。
- 不要把本机绝对路径写进 base 的通用 skill。

## 一句话记住

先给 AI 新项目路径和目录映射，让它生成 `project.agent.yaml`；后续迁移、替换、检查都以这份配置为准。

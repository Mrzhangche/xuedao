# 迁移后自检清单

迁移完成后，先过这张清单，再开始正式开发。

## 入口文件

- [ ] 新项目根目录存在 `README.md`
- [ ] 新项目根目录存在 `AGENTS.md`
- [ ] 新项目根目录存在 `project.agent.yaml`
- [ ] 新项目存在 `docs/README.md`
- [ ] 新项目存在 `skills/cool-project-stack/SKILL.md`

## 目录映射

- [ ] 后端目录映射正确
- [ ] 后台目录映射正确
- [ ] 移动端目录映射正确，或明确写了未启用
- [ ] `docs` 目录映射正确
- [ ] `skills` 目录映射正确

## Skill 路径

- [ ] 后端 skill 中的规则文件路径指向真实后端目录
- [ ] 后台 skill 中的规则文件路径指向真实后台目录
- [ ] Uni skill 中的必看目录指向真实移动端目录
- [ ] 目标项目不存在的规则文件已标注“如存在”
- [ ] 没有出现不存在的 `skills/api-dev`、`skills/admin-dev` 这类临时路径

## 文档内容

- [ ] 根 README 已经项目化，不再是 base 仓库说明
- [ ] `docs/README.md` 的推荐阅读顺序都能打开
- [ ] 差异文档名称与项目基线一致
- [ ] 示例业务已经换成当前项目合适的示例，或明确标注为通用示例
- [ ] 没有残留旧项目名、本机绝对路径、旧业务名

## 不能误替换的内容

- [ ] `src/modules/base` 保留原样
- [ ] `BaseService`、`BaseEntity` 等框架类名保留原样
- [ ] 技术栈名称保留原样，例如 cool-admin、Midway、Vue、Uni
- [ ] 官方文档链接没有被替换坏

## 迁移报告

- [ ] 已阅读迁移脚本输出的报告
- [ ] 已处理所有“需要人工确认”项
- [ ] 已确认跳过或备份的文件没有漏合并
- [ ] 已记录本次迁移来源和 base 版本

# 开发前检查

开始写代码前，先过一遍：

- [ ] 我知道这次是后端、后台、Uni，还是跨端任务
- [ ] 我知道这次属于 L1、L2、L3 还是 L4
- [ ] 我已经找到同类代码，不是准备从零乱写
- [ ] 我知道代码要放哪个目录、哪个文件附近
- [ ] 如果是新功能，我已经补了最少文档
- [ ] 如果已经进入开发前文档产出阶段，我已经写清《多 Agent 协作计划》或等价章节
- [ ] 多 Agent 计划里已经包含：Codex agent 角色、触发条件、适用阶段、输入文档、输出物、上下文范围、依赖顺序、人工确认点、冲突 / 返工处理
- [ ] 我已经判断本次是否需要拆 Codex 多 agent：L1 小改、单文件低风险、上下文很小、用户明确只要一个 agent 时一般不拆；L2+、跨端 / 跨模块、多阶段或高风险任务必须考虑拆
- [ ] 我没有直接开多个 Codex agent 并行乱跑；每个 agent 都只拿必要上下文，并且已明确交接和确认顺序
- [ ] 如果拆分 Codex 多 agent，我已经明确需求 / 文档审查、实现、测试补齐、代码审查、重构、回归验证等环节中哪些需要独立 agent
- [ ] 我已经判断：当前任务 / 当前项目是否已经需要建立“开发维护索引”
- [ ] 如果已经进入长期维护，`docs/README.md` 已能承担项目级入口
- [ ] 如果涉及重点模块，对应模块 `README.md` 已能承担模块级入口
- [ ] 如果这次会遇到项目私有坑、历史兼容点、项目偏差，我知道应该从哪份项目私有文档进入
- [ ] 如果这次任务要分阶段推进，任务执行卡已经和文档链路串起来，不是孤立记录
- [ ] 我确认后续维护者能沿着 `docs/README.md -> 项目开发维护索引 -> 模块 README / 项目私有坑位文档 / 任务执行卡` 找到入口
- [ ] 如果有接口变动，我已经补或确认了 API 文档
- [ ] 如果有数据库变动，我已经补或确认了数据库文档
- [ ] 我知道怎么自己验证这次改动
